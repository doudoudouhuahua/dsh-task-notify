# 配置与使用

[← 返回 README](../README.md)

配置持久化在 DSH settings 的 `task-notify` 命名空间（profile 的 `settings.yaml`），重启不丢。

## 入口：会话标题栏铃铛

点击铃铛打开 / 关闭配置面板，铃铛外观即当前状态：

| 外观 | 含义 |
| --- | --- |
| 空心，悬停「任务完成提醒（同步中）」 | 设置尚未从宿主拉取完成——不显示任何未经宿主确认的状态 |
| 实心 | 总开关已开 |
| 实心 + 右上角白色手机剪影 | 总开关已开，且 PushPlus 推送已开 |

## 配置面板

毛玻璃面板分三层折叠，底部为结果 / 错误提示行：

| 分组 | 内容 |
| --- | --- |
| 总开关（常驻） | 一键关闭全部通知 |
| 通知类型 | 7 个分类开关 + 「测试 Windows 通知」 |
| 手机推送 | 「PushPlus 推送」开关、Token 输入、保存 Token、测试手机推送 |

交互约定：

- **开关即改即存**：所有开关都没有「保存」按钮，改动立即写入宿主（串行化写入，快速连按互不覆盖）；
- **Token 需显式保存**：粘贴 Token 后点「保存 Token」或按回车；若未保存就点「测试手机推送」，
  会先自动落盘再发送；
- **分组状态记忆**：分组默认收起，展开 / 收起写入 localStorage，下次打开保持上次布局；
- **点击面板外任意位置关闭**（面板内点击与右上角 × 不受影响，点击铃铛仍是面板开 / 关切换）。

## 设置项总表

| 键 | 界面名称 | 默认 | 说明 |
| --- | --- | :---: | --- |
| `enabled` | 总开关 | 开 | 关闭后所有通道静默 |
| `agent` | 主回合 | 关 | 用户驱动的根会话回合结束（子代理完成由「子代理」负责） |
| `subagent` | 子代理 | 开 | 子代理结束时提醒 |
| `workflow` | 工作流 | 开 | 工作流结束时提醒 |
| `approval` | 需要审批 | 开 | agent 权限不足发起提权 / 越权审批（审批策略 `ask`） |
| `question` | 询问用户 | 开 | agent 调用 `ask_user_question` 后主动停下 |
| `plan` | 计划确认 | 开 | `/plan` 后 agent 调用 `exit_plan_mode` 提交计划 |
| `goal` | 目标受阻 | 开 | goal 自动回合因持续阻塞停止 |
| `push` | PushPlus 推送 | 关 | 同步推送到微信 |
| `token` | PushPlus Token | 空 | 一对一推送 token |

## 使用步骤

1. 点击标题栏铃铛 → 展开「通知类型」层 → 点「测试 Windows 通知」验证桌面通道；
2. 展开「手机推送」层，打开「PushPlus 推送」开关，粘贴 token → 点「保存 Token」（或按回车）→
   点「测试手机推送」验证手机通道；
3. 按需调整分类开关：「需要审批」「询问用户」「计划确认」「目标受阻」建议保持开启，
   「主回合」按需开启（它会对每个用户驱动的回合结束都提醒）。

### 接入 PushPlus（手机推送）

1. 在 https://www.pushplus.plus 扫码登录，复制「一对一推送」token；
2. 粘贴到面板的 Token 输入框并保存；
3. 点「测试手机推送」，微信应收到测试消息。

## 注意事项

> 审批策略为 `never`（如 `danger-full-access` 权限预设）时审批会被自动拒绝、无需人工操作，
> 因此不会发送审批提醒。

> 除 Token 外所有开关都是即改即存，无需「保存」按钮。
